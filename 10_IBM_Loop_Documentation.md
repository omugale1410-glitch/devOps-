# 10. IBM Loop Documentation

The IBM loop is treated as a repeating cycle rather than a one-time project stage. Each cycle uses observations to decide what should be changed or prototyped next.

| Cycle | Observation | Interpretation | Action |
| --- | --- | --- | --- |
| 1 | Students need a reliable place to find academic information. | Fragmented access creates unnecessary effort. | Prototype a student information dashboard. |
| 2 | Faculty repeatedly enters attendance information. | Attendance entry should minimize repetitive actions. | Prototype a streamlined attendance flow. |
| 3 | Administrators need consolidated academic summaries. | Reporting should bring related information together. | Prototype an academic report view. |
| 4 | Users may encounter confusing steps. | Navigation and forms need iterative usability checks. | Revise the interface and test again. |

## Iteration Principle

A prototype is not considered final merely because it works technically. The team should continue the observe–reflect–make cycle until the workflow is understandable and useful to its intended users.
