# 7. Non-Functional Requirements Specification (NFRS)

Non-functional requirements describe the quality attributes and operating expectations of the system.

| ID | Category | Requirement |
| --- | --- | --- |
| NFR-01 | Security | Protected academic information must only be accessible to authorized users. |
| NFR-02 | Usability | Screens should use understandable labels, predictable navigation and clear forms. |
| NFR-03 | Reliability | Saved records should remain consistent during normal system operation. |
| NFR-04 | Scalability | The architecture should accommodate increases in students, courses and records. |
| NFR-05 | Maintainability | Modules should be separated clearly enough to support future changes. |
| NFR-06 | Performance | Common searches and record operations should provide acceptable response times under expected institutional load. |
| NFR-07 | Availability | The service should remain available during normal academic operating periods. |
| NFR-08 | Privacy | Student information should be handled according to institutional access and privacy rules. |
| NFR-09 | Recoverability | Appropriate backup and recovery mechanisms should be considered for academic records. |
| NFR-10 | Compatibility | The web interface should work with commonly used modern browsers. |

## 7.1 Quality Focus

Security and data correctness are particularly important because the platform handles academic information. Performance targets should be finalized after expected user volume and infrastructure requirements are known.
