# 12. Product Roadmap

Development is divided into stages so that requirements can be validated before significant implementation effort is invested.

| Phase | Objective | Main Deliverables |
| --- | --- | --- |
| 1. Discovery | Understand users and define the problem | Personas, stakeholder analysis, BRD, requirements |
| 2. Experience Design | Visualize and validate key workflows | Wireframes and interactive prototypes |
| 3. MVP Build | Implement essential academic operations | Registration, records, attendance, reporting |
| 4. Verification | Test functionality and usability | Test cases, user feedback, defect fixes |
| 5. Expansion | Add validated future capabilities | Examination features, integrations, analytics and other approved modules |

## 12.1 Roadmap Principle

Each later phase should depend on evidence from the previous phase. The roadmap therefore prioritizes validation of the basic product before expanding its feature set.
