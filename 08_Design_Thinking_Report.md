# 8. Design Thinking Report

The project uses the five-stage Design Thinking cycle: **Empathize, Define, Ideate, Prototype, and Test**.

## 8.1 Empathize

The first activity is to understand students, faculty, administrators and examination staff. The investigation should focus on how academic information is created, maintained, retrieved and communicated today.

Key questions include:

- Where do users currently obtain academic information?
- Which tasks are repetitive?
- Where do errors or delays occur?
- Which information must remain restricted?

## 8.2 Define

**Problem statement:** Higher-education users require a coordinated way to manage student and academic information because fragmented processes can make attendance, examination, result and reporting activities harder to maintain.

## 8.3 Ideate

Potential concepts include:

- Centralized student profiles
- Role-specific dashboards
- Digital attendance workflows
- Examination/result modules
- Search and reporting tools
- Permission-controlled access

Ideas should be compared against user needs rather than selected only because they are technically interesting.

## 8.4 Prototype

Low-fidelity wireframes can be created for the highest-value workflows, such as student registration, attendance entry, record search and report generation.

## 8.5 Test

Representative users should perform realistic tasks on the prototypes. Feedback should be used to identify confusing navigation, missing information, unnecessary steps and permission issues before implementation.
