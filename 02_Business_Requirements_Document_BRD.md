# 2. Business Requirements Document (BRD)

## 2.1 Business Context

Higher-education institutions handle student information across several academic activities. When those activities rely on disconnected records or manual processes, maintaining consistency and retrieving current information can become difficult.

The proposed system addresses this by creating a common platform for core academic records and workflows.

## 2.2 Business Objectives

- Establish a central source for student and academic information.
- Reduce unnecessary dependence on scattered records.
- Give authorized users faster access to information relevant to their role.
- Standardize attendance and result-related processes.
- Produce academic reports in a consistent format.
- Create a base that can support future development.

## 2.3 Key Stakeholders

| Stakeholder | Main Interest |
| --- | --- |
| Students | Accurate personal, attendance and result information |
| Faculty | Efficient academic and attendance operations |
| Academic Administrators | Controlled student-record administration |
| Examination Staff | Reliable result entry and verification |
| IT Support | System availability, security and maintenance |

## 2.4 Business Requirements

1. The system must maintain student records.
2. Access must be controlled according to user roles.
3. Faculty must be able to manage attendance for assigned classes.
4. Examination staff must be able to enter and verify results.
5. Authorized users must be able to retrieve academic information.
6. The system should support structured academic reports.

## 2.5 Assumptions and Constraints

The solution is designed for a higher-education environment. User roles and institutional processes may differ between colleges, so detailed workflows should be validated with actual stakeholders. The first release is also constrained to the defined MVP rather than attempting to digitize every institutional process.
