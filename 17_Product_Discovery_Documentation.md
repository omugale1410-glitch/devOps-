# 17. Product Discovery Documentation

Product discovery is used to verify the problem and understand which workflows deserve attention before development.

## 17.1 Discovery Questions

- How are student profiles created today?
- Which roles need access to each category of academic information?
- Which activities require repeated data entry?
- How is attendance recorded, checked and corrected?
- How are examination results entered and verified?
- Which reports are required by administrators?
- What academic information should students be able to see themselves?
- Which information should remain restricted?
- Where do current processes produce errors or delays?
- What would make the proposed system easier to use?

## 17.2 Desired User Outcomes

**Student**
- Finds permitted academic information quickly.
- Understands attendance and result status.

**Faculty**
- Records attendance without unnecessary repetition.
- Can access the student information required for teaching work.

**Administrator**
- Maintains student records in an organized way.
- Can search and prepare academic reports.

**Examination Staff**
- Enters results accurately.
- Can complete verification before approved publication.

## 17.3 Discovery Hypotheses

The project assumes that fragmented academic workflows create avoidable effort and that a role-based centralized system could reduce this effort. These assumptions should be validated through interviews, observation and prototype testing rather than treated as proven facts.

## 17.4 Evidence to Collect

The next discovery stage should collect workflow examples, user feedback, common errors, access requirements and reporting needs. These findings should be converted into prioritized product requirements.
